# КОРОВАНЫ · кампания и PvP

Самостоятельная браузерная игра от первого лица по оригинальному ТЗ Кирилла. Создана с нуля для слепого музейного эксперимента: чужие реализации, их код, README и скриншоты не использовались. Из общих файлов прочитан только формат музейной карточки и таблицы.

**[Исходная музейная версия](https://rai220.github.io/korovany/gpt-6-astra/)** · [Скриншот](screen.jpg)

## Запуск

Публичная игра: **https://korovany.zetoqqq.ru/** · **[PvP](https://korovany.zetoqqq.ru/arena/)**.
Резервный адрес: https://zetoqqq.ru/korovany/ (обновляется только ручным деплоем).
Деплой и обслуживание: [deploy/README.md](deploy/README.md).

Нужны Go 1.23+ и Node.js 22.12+ (или 24 LTS). Three.js закреплён в `package-lock.json` и входит в сборку: CDN во время игры не требуется.

```sh
npm ci
make build
./bin/korovany
```

Откройте http://127.0.0.1:8080/arena/ для PvP или http://127.0.0.1:8080/ для одиночной кампании. Создайте комнату, передайте код другу и войдите во втором браузере. Сетевая кнопка есть в верхней части меню кампании.

Для игры в локальной сети:

```sh
./bin/korovany -addr :8080
```

Остальные игроки открывают `http://<адрес компьютера в сети>:8080/arena/`. В приглашении должен быть адрес, доступный другим игрокам: ссылка с `127.0.0.1` работает только на компьютере создателя. Если захват мыши недоступен по HTTP, остаются перетаскивание и стрелки. Для интернет-хостинга нужен доступный сервер и HTTPS/WSS через обратный прокси. По умолчанию сервер слушает только локальный интерфейс.

Для разработки запустите два процесса:

```sh
# Терминал 1: сервер с разрешёнными адресами Vite
go run ./cmd/korovany -origin localhost:5173,127.0.0.1:5173
# Терминал 2: клиент с автоматическим обновлением
npm run dev
```

Vite передаёт `/api` и `/ws` серверу на порту 8080. В обычном запуске Go раздаёт готовую папку `dist`; рядом с бинарником должна быть эта папка (или укажите `-assets /путь/к/dist`). Прямой запуск исходного `index.html` через `file://` заменён HTTP-сборкой. Сохранения кампании по-прежнему используют прежний ключ localStorage, но доступны только на прежнем origin: схема, адрес и порт должны совпадать.

## Сетевая схватка

Первый игровой срез — отдельная арена на 2–8 игроков, каждый сам за себя. Матч начинается после появления второго бойца и трёхсекундного отсчёта. Победа: 10 убийств или лучший счёт за 3 минуты; одинаковый счёт даёт ничью. Через 10 секунд начинается следующий раунд. Это ещё не командное ограбление движущегося корована.

- WASD — движение, Shift — бег, пробел — прыжок; мышь или стрелки — обзор.
- 1 — клинок, 2 — лук; оружие также переключается кнопками внизу справа. ЛКМ / E — удар клинком; с луком удерживай для натяжения и отпускай для выстрела. ПКМ / Q — большой щит с клинком или отмена натяжения лука.
- Лук выдаётся всем: 20 стрел, пополнение после возрождения и в новом раунде. Полное натяжение занимает 1 секунду; раньше 0,2 секунды стрела не выпускается. Сила натяжения определяет скорость (до 28 м/с) и урон (до 34), выстрел расходует 8 выносливости, пауза после выпуска — 0,4 секунды. Стрела летит по дуге под действием гравитации (12 м/с²), до 20 м — примерно 0,7 секунды; предельный путь — 55 м. На расстоянии нужно брать выше цели и упреждать её движение. Сервер проверяет столкновения во время полёта: можно увернуться, закрыться блоком или уйти за укрытие. Натяжение видно на модели и шкале у прицела; меню, потеря фокуса и смена оружия отменяют натяжение.
- Меч: 9 тиков замаха (0,15 с), 10 тиков активного удара, затем восстановление до общей задержки 32 тика. Сервер ведёт клинок по той же дуге, что показывает модель, и проверяет столкновения на промежуточных положениях. Удар фиксирует направление при начале, учитывает наклон прицела, останавливается на первой цели или укрытии и не наносит повторный урон за один взмах. Во время замаха можно увернуться; смена оружия, смерть, отключение или потеря правой руки прерывают удар.
- Попадания меча и стрел считаются по отдельным повёрнутым объёмам головы, корпуса, левой/правой руки и левой/правой ноги. Объёмы совпадают с размерами и позами модели, включая ходьбу, замах, блок и натяжение лука. Между конечностями и рядом с головой можно промахнуться; потерянная конечность больше не принимает попадания.
- Урон по общему здоровью: голова ×2, корпус ×1, руки ×0,4, ноги ×0,65, с округлением до целого. Отдельная прочность руки — 50, ноги — 65; она расходуется базовым уроном после блока. При нуле конечность теряется до возрождения. Без любой руки нельзя стрелять из лука (текущее натяжение отменяется), без правой — бить мечом и блокировать, без любой ноги — ходить, бежать и прыгать. Повреждённая нога постепенно замедляет движение. Переподключение травмы не лечит.
- Попадания отталкивают живых игроков с затуханием и проверкой препятствий. Манекены закреплены на месте. Частицы удара и падающие конечности — визуальные эффекты; на прицеле показываются часть тела, урон и блок, рядом со здоровьем — травмы и ограничения.
- При защите с клинком поднимается большой щит во весь рост. Попадания клинка и стрел в его поверхность полностью блокируются без урона здоровью и конечностям; щит расходует 8 выносливости за попадание. Защита действует только там, где находится щит: сбоку и со спины тело уязвимо. С поднятым щитом ускорение недоступно. Лук блокировать не позволяет; смена оружия не сбрасывает задержку атаки. Выбранное оружие сохраняется при возрождении, а при переподключении сохраняется и остаток стрел.
- Для тестирования при натяжении лука включена пунктирная траектория с кольцом в конце полёта: на земле, укрытии или пределе дальности. Она учитывает текущий натяг, угол прицела, гравитацию и дальность. Движение противника не прогнозируется. Подсказку можно отключить: **P / меню → Траектория лука (тест)**.
- Смерть оставляет 3 секунды до возрождения. Короткая защита после появления снимается при атаке.
- **8-битный звук**: взмах меча, попадание, звон щита, натяжение и выстрел лука, получение урона, нехватка выносливости при попытке атаки, убийство и смерть. Отсчёт, начало и результат матча сопровождаются короткими сигналами. Свои атаки звучат сразу, попадания — по подтверждению сервера; чужие бои не заглушают твой. **P / меню → Звук**: общий выключатель и громкость, включая сэппуку; настройки сохраняются в браузере. При потере фокуса звук прекращается. Всё синтезируется локально через Web Audio, без загрузки аудиофайлов.
- **Shift + K** открывает подтверждение сэппуку (та же клавиша в русской раскладке — **Shift + Л**). Также доступно через **P / меню → Сэппуку · сдать раунд → Совершить сэппуку** — автоматическое поражение до следующего раунда, даже при лучшем счёте. Добавляется одна смерть без убийства кому-либо; атаки и выпущенные стрелы прекращаются. Если остался один участник, схватка завершается его победой; при нескольких оставшихся бой продолжается. Переподключение поражение не отменяет. Сцену с коленопреклонением, клинком и падением видят все; у сдавшегося бойца — камера от третьего лица, искры, звук и экран поражения. Звук отключается в меню; системная настройка уменьшения движения убирает вспышку, тряску и облёт камеры.
- Для тренировки одному создай комнату, открой **P / меню → Манекены → Добавить манекена**. Манекены стоят на месте, не атакуют и не блокируют; меч, лук, урон и счёт работают по обычным правилам PvP. После смерти манекен возрождается на своей точке через 3 секунды с обычной защитой после появления. Здоровье видно в списке бойцов. Любой игрок комнаты может добавлять манекенов и убрать их всех через меню; они занимают общие места (до 8 бойцов) и видны всем участникам. Одного игрока и манекена достаточно для начала раунда.
- P / меню — настройки и выход. Меню, потеря фокуса и скрытие вкладки не останавливают общий мир.
- При кратком обрыве клиент пробует вернуться с приватным токеном той же сессии. Сервер сохраняет бойца 20 секунд. Токен живёт в памяти вкладки; перезагрузка страницы считается новым входом.
- Комнаты и результаты хранятся в памяти; перезапуск сервера завершает матчи. Пустая комната удаляется через 30 секунд.

Сейчас транспорт — **WebSocket**, судья матча — Go-сервер. Меч учитывает задержку через серверную историю состояний. Стрелы сталкиваются с текущими положениями игроков и укрытий без отката времени, чтобы сохранялась возможность увернуться. WebRTC/P2P, автоматический обход NAT/TURN, перенос хоста и перенос кампании в сетевую симуляцию пока не реализованы. Хостить этот сервер на компьютере игрока можно, но это обычное клиент-серверное подключение, не автоматический P2P.

## Устройство сетевой части

- `internal/game` — чистая симуляция без браузера и сети: 60 фиксированных шагов в секунду, движение, бой, возрождение, фазы раунда.
- `internal/game/data/arena.json` — единые препятствия, точки появления и параметры. Go встраивает файл, TypeScript импортирует его при сборке. При изменении контракта карты нужно обновить `version` и пересобрать обе части.
- `internal/server` — HTTP, комнаты и адаптер WebSocket. Состоянием каждой комнаты владеет одна goroutine; обработчики соединений передают команды через ограниченную очередь. Медленный клиент не задерживает остальных. Максимум 64 комнаты.
- `client/protocol.ts` — типы сообщений; `network.ts` — подключение, ping и восстановление связи. Протокол и версия карты проверяются при входе.
- `client/simulation.ts` — предсказание собственного движения и доступности атаки, повтор неподтверждённых команд после коррекции, буфер интерполяции остальных бойцов (100 мс). Снимки сервера отправляются 20 раз в секунду. Прогноз учитывает выносливость, стрелы и общий интервал атак; подтверждение не повторяет анимацию. Урон и маркер попадания приходят только с сервера.
- `client/render` — сцена и модели. Генератор персонажей общий для кампании и сетевого клиента; игровые данные не содержат Three.js-объектов.
- `client/input.ts`, `client/main.ts` — управление и интерфейс. Кампания пока остаётся в `game.js`, кроме вынесенных моделей персонажей.

Клиент отправляет намерение движения и атаки, номер жизни и время отображённого состояния с парой опорных снимков, без координат, урона и длительности шага. Сервер проверяет диапазоны, монотонные номера команд, частоту сообщений, дальность и направление атаки, препятствия, выносливость, задержку между ударами и защиту после появления. За тик исполняется максимум одна команда игрока. После сетевого всплеска очередь сокращает устаревшие повторяющиеся команды до двух тиков, сохраняя отдельные клики, прыжки, отпускание блока и первую возможную атаку с исходными направлением и временем. Пропущенное движение исправляется обычным подтверждением команд; ускорения симуляции нет. Это основа серверной проверки правил, а не полноценная система античита.

Компенсация ударов клинком хранит 500 мс истории и один граничный снимок; предел отката — 350 мс, включая интерполяцию и очереди. Сервер сам измеряет RTT уникальными запросами `probe` / `probe_ack`, учитывает колебания задержки и проверяет время команды. До первого замера используется обычная проверка без отката. Положение цели, позы конечностей и направленный блок восстанавливаются на копиях по тем же снимкам, что отображал клиент; время этой истории продвигается вместе со взмахом, позволяя уйти во время замаха; здоровье и номер жизни проверяются также в настоящем. Старые и недостоверные удары отклоняются без отмены движения и расхода ресурсов. Целевой RTT — 200 мс; при 300 мс вместе со сглаживанием или при длительных зависаниях полная компенсация может превышать предел. Для клинка возможен запоздалый урон после ухода за укрытие в пределах окна. Для стрел откат не применяется: сервер считает натяжение по своим шагам, а полёт и попадания — по текущему миру.

Протокол версии **6** требует совместного обновления сервера и клиента. Команды `add_dummy` / `remove_dummies` управляют манекенами комнаты; `dummy_result` возвращает сообщение о результате, поле `dummy` отмечает манекен в снимке игрока. В снимке игрока `lastAttackSeq`, `attackWeapon` и `nextAttackTick` связывают подтверждение с предсказанием, а `bowDrawTicks` передаёт натяжение лука. Поле `projectiles` содержит летящие стрелы; команда `cancelAttack` отменяет натяжение. `lastCombat` содержит последнюю причину результата (`swing`, `flying`, `hit`, `miss`, `rejected`), номер команды, оценку её возраста, ожидание в очереди и глубину отката в миллисекундах. Поля `limbDamage`, `gait`, `impulseX/Z`, `attackYaw/Pitch` передают состояние конечностей, движения и замаха; событие `hit` содержит `part` (включая `shield` для щита), `to`, `blocked` и `severed`. Геометрия, коэффициенты урона и ключевые позы задаются в `internal/game/data/combat.json`; `pose_cases.json` проверяет совпадение серверных объёмов с трансформациями Three.js.

`peer` в сервере и `Transport` в клиенте отделяют сеть от симуляции. Следующий этап для прямых соединений: адаптер Pion/WebRTC, сигналинг, ICE/STUN и TURN, отдельный запуск Go-хоста у игрока. Одной замены WebSocket недостаточно, чтобы обещать меньшую задержку или равные условия с хостом.

Дальше — испытания при потерях пакетов, командный режим сопровождения/ограбления корована, затем перенос NPC и других механик кампании. Полный рефакторинг одиночной симуляции и её привязки ко времени кадров остаётся отдельным этапом.

Ниже описана **одиночная кампания** и её исходные механики.

## Три судьбы

- **Лесной эльф:** отразить набег на деревянную деревню, ограбить корован, прорваться во дворец и поднять знамя леса. Начинает с луком и клинком.
- **Дворцовая стража:** войти в южные ворота, найти командира в золотом шлеме и получить приказ. Защитить дворец от троих шпионов и партизан, лично доложить, получить награду и двух спутников, уничтожить отмеченный дозор у старого форта, вернуться с докладом.
- **Злой. Имя не придумал.:** начать у старого горного форта с четырьмя воинами. Самостоятельно командовать: «за мной», «держать позицию», «на штурм дворца». Армия идёт по восточному тракту к южным воротам. Игрок участвует в бою и захватывает знамя после уничтожения защитников.

Каждая история имеет завершение и награду. Затем продолжается свободная игра. Примерно раз в 110 игровых секунд враги нападают на родное поселение; без защиты они разграбляют его и отнимают часть золота. Окна интерфейса ставят мир на паузу.

| Покупки | Четыре лавки с лекарями: бинты, стрелы, доспех, усиление оружия, наёмники, коляска, три протеза. Тратится реальное игровое золото; уровни улучшений и размер отряда ограничены. |
| Командир и самокомандование | Два последовательных приказа для стражи с личными докладами. Злодей управляет отрядом и штурмует дворец. Все фракции могут нанимать спутников. |
| Рука | Утрата ослабляет удары на 52% и вызывает смертельное кровотечение. Бинт / лекарь останавливает кровь, механическая рука возвращает силу. |
| Глаз | Утрата закрывает чёрным ровно левую половину экрана. Стеклянный волшебный глаз возвращает обзор. |
| Нога | Утрата вызывает кровотечение, снижает высоту камеры и оставляет ползание. Коляска позволяет ехать быстрее, но без прыжка. Протез возвращает обычное движение. |
| Сохранения | localStorage: ручная запись F5, загрузка F9, автозапись каждые 60 игровых секунд и при уходе со страницы. Сохраняются фракция, прогресс, травмы, деньги, отряд, живые враги, трупы и их обыск, корованы и таймер набегов. Повреждённые записи отклоняются. |

Травмы игрока возможны при неблокированном попадании, когда здоровье ниже 83; между травмами есть 20 секунд передышки. Кровотечение само не останавливается. Врага можно ранить в руку, ногу или голову в зависимости от точки попадания; потеря ноги замедляет его, руки — ослабляет.

## Упрощения

Это законченная небольшая игровая диорама размером около 400 × 400 шагов, а не масштаб Daggerfall. Магазин — меню обмена, без интерьеров, сложной экономики и генерации городов. Дипломатия фиксирована: три воюющие стороны и нейтральные торговцы. Бой и движение войск используют простое локальное избегание препятствий и путевые точки; сложного поиска пути нет. Трупы и отлетающие конечности — стилизованные геометрические модели без физического ragdoll. У коляски видны объёмные колёса, подлокотники и подножка от первого лица; отдельной внешней модели игрока нет. Стеклянный глаз намеренно волшебный. Все иллюстрации и модели процедурные, без скачанных художественных ассетов.

Для ограничения нагрузки остаются до 20 тел и 24 отделённых частей. Лес рисуется несколькими пакетами, разрешение ограничено. Автоматическое качество снижает разрешение и отключает тени при низком FPS; обычное и лёгкое качество можно выбрать вручную. В этом окружении headless Chromium с программным SwiftShader показал около 13 FPS после автоматического снижения внутреннего разрешения до 704 × 440 при окне 1280 × 800. Это не замер на ноутбуке с аппаратным GPU; его производительность здесь не проверялась. Счётчик FPS включается в меню паузы.

## Проверка

```sh
make check                     # TypeScript, клиентские тесты, Go с -race, go vet
make build
npx playwright install chromium
./bin/korovany                  # оставить работающим в отдельном терминале
npm run test:campaign           # регрессии одиночных механик и обычного запуска
npm run test:multiplayer        # два браузера: комната, движение, бой, меню, reconnect
npm run test:latency            # движущиеся цели, RTT 200 мс, разные задержки и jitter
```

Go-тесты проверяют движение, стены, направленный блок, дальность и частоту ударов, стрельбу с учётом вертикального прицела, укрытий, боезапаса и смены оружия, смерть и возрождение, лимиты комнаты, повторы/некорректные команды, возврат игрока и изоляцию комнат. Сетевые тесты используют реальные WebSocket-соединения и сверяют состояния двух клиентов. Общие численные сценарии движения из `movement_cases.json` запускаются в Go и TypeScript; клиентские проверки дополнительно проверяют коррекции, смену жизни и интерполяцию.

Кампания использует явные фикстуры `?test=1` для сложных состояний; в обычном запуске тестовый API отсутствует. Сетевой браузерный тест управляет реальными клавишами и наблюдает публичные сообщения сервера, без изменения игрового состояния через тестовый API. Для другого сервера укажите `ASTRA_URL=http://127.0.0.1:8080/` (с завершающим `/`). Проверки подключены к GitHub Actions.

`screen.jpg` — исходный скриншот одиночной игры. Приведённый выше старый замер SwiftShader относится к исходной кампании, а не к текущей сетевой арене. Проверка через localhost не заменяет испытания между разными сетями.

Для покадровой проверки PvP-анимации запусти `npm run dev` и открой `/tests/combat-preview.html`: ползунок показывает замах, удар и восстановление, выбор состояния — отсутствие конечностей и позу лука. Эта тестовая страница не входит в production-сборку.
